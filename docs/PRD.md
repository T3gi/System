# Product Requirements Document (PRD): Автоматизована система вентиляції

## 1. Концепція продукту
Система розумної вентиляції для приміщень, що автоматично керує повітряним потоком на основі температурних показників та візуальних команд (жестів). Головна мета — забезпечення енергоефективного клімат-контролю з можливістю безконтактного ручного перевизначення (override) стану системи.

## 2. Апаратні залежності
* **Контролер:** STM32 Nucleo-F411RE.
* **Сенсор 1: Модуль GY-89**
  * **Інтерфейс:** I2C.
  * **Навіщо у проєкті:** Для безперервного моніторингу клімату (реалізує вимогу **FR-01**).
  * **Альтернативи:** Датчик DHT11 (відкинуто через низьку швидкість опитування та меншу точність).
* **Сенсор 2: Камера OV7670**
  * **Інтерфейс:** DCMI/I2C.
  * **Навіщо у проєкті:** Для розпізнавання керуючого жесту (реалізує вимоги **FR-04, FR-05**).
  * **Альтернативи:** Датчик руху HC-SR501 (відкинуто, оскільки він реагує на будь-який загальний рух, а не на цілеспрямовану команду користувача).
* **Виконавчий механізм: Сервопривід Tower Pro SG92R**
  * **Інтерфейс:** PWM (ШІМ).
  * **Навіщо у проєкті:** Для фізичного відкриття та закриття заслінки (реалізує вимогу **FR-02**).
  * **Альтернативи:** Кроковий двигун (відкинуто через надмірні габарити та необхідність використання додаткового зовнішнього драйвера).
* **Сховище даних: SPI-flash W25Qxx**
  * **Інтерфейс:** SPI.
  * **Навіщо у проєкті:** Для логування подій, фіксації часу та причини спрацювання (реалізує вимогу **FR-07**).
  * **Альтернативи:** Внутрішня пам'ять мікроконтролера (відкинуто через швидкий знос циклів перезапису при постійному логуванні).

## 3. Функціональні вимоги
* **FR-01: Температурний моніторинг:** Система повинна безперервно зчитувати дані про температуру з датчика GY-89.
* **FR-02: Температурний тригер:** Система повинна генерувати ШІМ-сигнал для повороту сервопривода на 90 градусів (відкриття вентиляції), якщо температура перевищує заданий поріг (наприклад, 26°C).
* **FR-03: Гістерезис клімат-контролю:** Система повинна автоматично закривати заслінку лише після того, як температура впаде на 2°C нижче порогу відкриття (до 24°C), для уникнення постійного "смикання" сервопривода.
* **FR-04: Візуальний моніторинг:** Система повинна безперервно захоплювати кадри з камери OV7670.
* **FR-05: Візуальний тригер:** Система повинна змінювати стан заслінки на протилежний при виявленні заздалегідь визначеного патерну (наприклад, перекриття об'єктива рукою або розпізнавання руху в певній зоні).
* **FR-06: Блокування автоматики:** Система повинна блокувати температурний контроль на наступні 5 хвилин після спрацювання візуального тригера.
* **FR-07: Журналювання подій:** Система повинна записувати кожну зміну стану вентиляції (відкрито/закрито) та джерело команди ("Спрацював датчик температури" або "Спрацювала камера") у зовнішню пам'ять W25Qxx по шині SPI.
* **FR-08: Індикація стану:** Система повинна вмикати вбудований на платі LED-індикатор, коли заслінка відкрита, і блимати ним у момент запису логів у флеш-пам'ять.

## 4. План тестування (Критерії приймання)
* **FR-02: Температурний тригер** -> Тест №1 (Стрес-тест температури): Штучно нагріти датчик GY-89 (наприклад, подихом або теплим предметом). Очікуваний результат: сервопривід повертається, відкриваючи вентиляцію, у термінал UART виводиться повідомлення про подію.
* **FR-05: Візуальний тригер** -> Тест №2 (Оптичний override): Привести систему в закритий стан за кімнатної температури. Зробити заданий жест перед камерою. Очікуваний результат: сервопривід негайно відкриває заслінку.
* **FR-07: Журналювання подій** -> Тест №3 (Читання логів): Перезавантажити мікроконтролер кнопкою Reset. Очікуваний результат: під час старту система вичитує з пам'яті W25Qxx останні збережені події та виводить їх історію у UART-термінал комп'ютера.
