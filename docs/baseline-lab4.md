# Базова лінія продуктивності Super Loop (Baseline)

Цей документ фіксує найгірші показники швидкодії та використання пам'яті, отримані під час тестування системи з архітектурою Super Loop (у режимах максимального навантаження, таких як передача зображення, та при імітації апаратних збоїв). 

Ці дані слугуватимуть еталоном (baseline) для порівняння після переходу на багатозадачну операційну систему FreeRTOS у Лабораторній роботі №4.

## 1. Показники швидкодії (Часові метрики)

| Метрика | Найгірше зафіксоване значення | Причина деградації у Super Loop | Очікування після впровадження FreeRTOS |
| :--- | :--- | :--- | :--- |
| **Затримка реакції на кнопку (max)** | **107.17 мс** | Основний цикл був заблокований тривалими операціями роботи з камерою. | Зменшення до мікросекунд (завдяки витісненню довгої задачі). |
| **Джитер циклу TICK (max)** | **> 2000 мс** | Відправка масиву даних (22 КБ Base64) блокуючою функцією UART. | < 1-2 мс (забезпечення жорсткого розкладу для задачі TICK). |
| **Завантаження процесора (LOAD)** | **100%** | Busy-waiting цикли очікування звільнення шин (SPI/UART/I2C) всередині HAL. | Значне зниження (задачі переходитимуть у Blocked state, віддаючи CPU). |
| **Час відновлення (I2C timeout)** | **~1000 мс** | Послідовне очікування відпрацювання апаратного таймауту. | Асинхронна обробка без зупинки інших, більш пріоритетних задач. |

## 2. Використання пам'яті

| Метрика пам'яті | Значення (Super Loop) | Характеристика | Очікування від FreeRTOS |
| :--- | :--- | :--- | :--- |
| **Кількість стеків** | 1 | Вся програма ділить один загальний стек (Main Stack Pointer). | Кожна задача отримає власний ізольований стек (Process Stack Pointer). |
| **Максимальна глибина стека** | **~1.6 КБ** | Викликано глибокою вкладеністю функцій HAL та обробників переривань. | Загальне споживання RAM суттєво зросте через TCB (Task Control Blocks). |
| **Статична пам'ять (BSS/Data)** | Базовий рівень | Використання багатьох глобальних прапорців (напр., `btn_pending`). | Зменшення кількості "сирих" глобальних змінних на користь механізмів ОС (Queues). |

## Висновок

Впровадження FreeRTOS у ЛР4 вимагатиме **більше ресурсів пам'яті** (RAM) на підтримку контекстів задач. Проте це є прийнятною "ціною" за **радикальне покращення часових метрик**, зокрема усунення джитера в 2 секунди та зменшення затримки реакції системи на зовнішні переривання.
